## [Greedy] 백준 - 1931. 회의실 배정

> **핵심 키워드:** *#그리디 #정렬 #회의실배정 #ActivitySelection*

[https://www.acmicpc.net/problem/1931](https://www.acmicpc.net/problem/1931)

### 1. 💡 핵심

* > **"회의실이 하나라면, '빨리 끝나는 놈'부터 집어넣는 것이 뒤를 위해 가장 이득이다!"**


* **종료 시간 기준 정렬:** 회의가 일찍 끝날수록 남은 시간이 많아져 더 많은 회의를 선택할 수 있는 기회가 생김.
* **그리디 선택:** 현재 선택할 수 있는 회의 중 가장 빨리 끝나는 것을 선택해 나가는 것이 정답.

---

### 2. 주의 사항

* **시행착오 - 강의실 배정(11000)과의 차이:**
  * **11000번:** 모든 강의를 다 하기 위해 '강의실'을 추가함 $\rightarrow$ `heap`으로 여러 종료 시간 관리.
  * **1931번:** 한정된 공간에 최대 개수를 쑤셔 넣음 $\rightarrow$ `greedy`로 하나의 종료 시간만 추적.

  * 비슷해 보이는 문제라도 **최소 리소스(강의실)를 구하느냐** 아니면 **한정된 리소스에서 최대 효율을 뽑느냐**에 따라 도구가 완전히 달라짐. 
  * 회의실이 하나라면 무조건 **빨리 끝나는 곳**부터 챙기기 🔥


* **정렬 조건 (중요):** 종료 시간이 같을 경우 **시작 시간**도 오름차순으로 정렬해야 함.
  * 이유: `(2, 2), (1, 2)` 순서로 있다면 시작 시간이 늦은 `(2, 2)`가 먼저 선택되어 `(1, 2)`를 놓칠 수 있기 때문. <br>(시작과 동시에 끝나는 회의 고려)


* **시간 복잡도:** 정렬에 $O(N \log N)$, 탐색에 $O(N)$이 소요되어 $N=100,000$을 충분히 처리.

#### + 🧸 Related concepts

* **Interval Scheduling:** 겹치지 않는 최대 구간을 찾는 전형적인 알고리즘 문제.
* **Fractional Knapsack:** 그리디로 풀 수 있는 또 다른 대표적 유형.

---

### 3. 코드 설계 흐름

1. **입력 및 저장:** 회의 시작 시간($s$)과 종료 시간($e$)을 튜플로 리스트에 담음.
2. **정렬:** **1순위 종료 시간($e$)**, **2순위 시작 시간($s$)** 기준으로 오름차순 정렬.
3. **순회:** 리스트를 하나씩 확인하며 현재 회의의 시작 시간($s$)이 직전 회의의 종료 시간(`end`)보다 크거나 같은지 확인.
4. **갱신:** 조건 만족 시 회의 개수(`count`)를 늘리고, `end`를 현재 회의의 종료 시간으로 갱신.

---

### 4. ☁️ 최종 정답 코드

```python
import sys

input = sys.stdin.readline
n = int(input())
time_table = []

# 1. 모든 회의 시간 정보를 입력받아 리스트에 저장
for _ in range(n):
    s, e = map(int, input().split())
    time_table.append((s, e))

# 2. ⭐️ 핵심: 종료 시간 기준 정렬 (종료 시간이 같다면 시작 시간 기준 정렬)
# 빨리 끝나는 회의를 먼저 선택해야 뒤에 더 많은 회의를 배치할 수 있음
time_table.sort(key=lambda x: (x[1], x[0]))

end = 0  # 현재 사용 중인 회의가 끝나는 시점
count = 0  # 최대한 배정된 회의의 총 개수

for s, e in time_table:
    # 3. 현재 검사하는 회의의 시작 시간이 
    # 직전 회의가 종료된 시간 이후라면 배정 가능!
    if s >= end:
        end = e  # 회의실이 다음에 비는 시간을 현재 회의의 종료 시간으로 갱신
        count += 1 # 회의 개수 추가

print(count)

```
